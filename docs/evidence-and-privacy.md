# Evidence and Privacy Rules

## Separate three kinds of statements

- **Reported:** what an owner, technician, seller, or public post says happened.
- **Observed:** what is directly visible or measured in retained evidence.
- **Inferred:** a technical interpretation that may later be disproved.

Never rewrite a report or inference as an observed fact.

## Evidence handling

- Prefer original files over screenshots and compressed social-media copies.
- Retain original filenames and file hashes in the private working record.
- Create derived crops or annotations as separate files.
- Record who owns each item and the permission granted for it.
- Photograph the full board before close-ups so every macro image can be located.
- Include a scale when component dimensions matter.
- Record instrument, mode, reference node, stimulus, current limit, and units.

## Public-post leads

A public post may establish that a repair problem was reported. It does not grant permission to copy photographs, names, profile images, or private communications into this repository. Until permission is documented:

- summarize the technical report;
- omit identifying information;
- do not republish screenshots or images; and
- label the case `lead` and `unverified`.

## Redaction

Remove serial numbers, account identifiers, faces, profile photographs, precise locations, shipping labels, QR codes, and unrelated personal material. Preserve an unredacted item only in a controlled private record when genuinely necessary.

## Corrections

Keep the earlier claim visible in case history, mark it superseded, and cite the evidence that changed the conclusion. A failed hypothesis is useful diagnostic data, not an embarrassment to be quietly launched into the sun.
